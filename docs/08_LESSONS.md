# 08 · 踩坑记录：三个把我带偏的判断

这一篇不是流水账，只写**判断错在哪、为什么错、怎么发现的**。
如果你也在用 VLA 做真机任务，希望这几页能省你几天。

---

## 错误一：把 loss / 单步误差当验收标准

### 当时的想法

> loss 从 0.15 降到 0.08，回放单步误差中位 1.4° —— 模型拟合得很好，问题一定在别处。

于是花了大量时间排查：相机被挪了？数据有脏样本？动作头没训上？归一化算错了？
限速截断了？示教顺序单一？

### 为什么错

`loss`、`120 开卷回放`、`单步误差` 是**同一个东西**：teacher-forced 监督误差。
每一步都喂真值状态，误差被锚死在原地，不会累积。

所以它对"闭环失效"是**结构性失明**的。更糟的是，它还能给出很高的分数：

- 数据时间轴错位（图像超前 4 秒）时，loss 依然能拟合到 0.08 ——
  因为"图像(t+63) + 状态(t) → 动作(t)"在训练集内部是自洽的。
- 模型输出退化成 `a ≈ s + 常数`（纯随动、零回拉）时，loss 也照样低。

### 后来怎么发现的

用 `122_correction_gain` 算雅可比 ∂T/∂s，得到 **0.83~1.10** —— 这意味着
"把状态扰动 2°，输出也跟着变 2°"，也就是**输出 = 当前状态 + 常数**。
闭环里一旦偏 5 cm，它就带着这 5 cm 一路走下去。

再配合 `126` 的闭环合爪散布比（只有演示的 46%），才看清：模型给的是"平均位置"。

### 改用什么

| 想知道 | 该测 |
|---|---|
| 拟合得好不好 | loss / 120（够用，但别当结论） |
| 有没有回拉能力 | **122 雅可比增益** |
| 会不会模式坍缩 | **126 输出散布比** |
| 数据本身对不对 | **124 审计 + 133 对齐检查** |
| 到底能不能用 | **真机 CSV：act vs fb、FK 轨迹、合爪读数** |

## 错误二：想用"裁数据"解决"起点不统一"

### 当时的想法

v3 抓的是"桌面上所有物体"，一集里有 3~5 次抓取。想着把它切成
"一次抓取—放置"的子任务（515 段），每段起点都从盒子上方开始，粒度统一，应该更好学。

### 实测打脸

排除每集第一段后，剩下 413 个子任务的**起点离散度**：

| 关节 | 起点 std | 全集 std | 比值 |
|---|---|---|---|
| **pan** | **30.8°** | 22.4° | **1.38** |
| lift | 17.0° | 40.2° | 0.42 |
| **elbow** | **26.9°** | 41.5° | 0.65 |
| **wr** | 26.0° | 25.8° | 1.01 |

**pan 的起点标准差（30.8°）比整条演示里所有帧的离散度（22.4°）还大。**

原因很朴素：**裁剪只能"切"，不能"把臂搬回同一起点"。**
每段演示结束时的姿态取决于"上一个物体在哪儿、抓完手往哪收"，本来就各不相同。

于是同一个指令 `pick and put` 对应了 400 多种起始姿态，模型只能学出"平均起步"。

### 更糟的一次

后来为了绕开"起点压在关节极限"的问题，把数据每集多裁了 10 帧。
结果起始位姿的 std 从 **3.77°（lift）放大到 13.50°** —— 把数据里最宝贵的"所有集从同一位姿起跑"
这个优点直接打散了。

**教训：想改起点，改客户端，不要改数据。**

### 正确的做法

在**采集协议**里把 home 写进去：

```
抓一个物体 → 放进盒子 → 回到固定 home（停 0.3~0.5 秒）→ 抓下一个 → …
```

这样一条演示里有 N 个自然边界，而且每个边界都是**同一个位姿**，
切出来的子任务起点 std ≈ 0，客户端也从同一个 home 出发，训练与部署完全一致。

## 错误三：以为"起点统一"就该"时刻统一"

### 当时的想法

每集裁掉的静止帧数是 46~124 帧不等（中位 78），所以"每条演示的第 0 帧在原始时间轴上位置不同"。
既然要统一，那就固定裁 78 帧？

### 实测

| 切法 | 首帧 lift std | 首帧 elbow std |
|---|---|---|
| **固定裁 78 帧**（时刻统一） | **18.09°** | **15.46°** |
| **按"运动开始"裁**（位姿统一，实际采用） | **3.77°** | **2.41°** |

固定帧数会让位姿分散 5 倍：有的集静止段只有 46 帧（切到第 78 帧时早就在动了），
有的有 124 帧（还在静止区）。

**"统一位姿"和"统一时刻"不可能同时做到**，而时间轴对模型没有意义
（观测里只有关节角和图像，没有时间戳）。所以选位姿。

唯一确实不统一的是**第 0 帧的运动速度**（0.18~4.48 °/帧，差 25 倍）。
试过改成"按速度阈值对齐"（0.8/1.0/1.5/2.0/2.5 °/帧），**修不好**：
速度 std 只从 0.86 降到 0.50，而 elbow 的位姿 std 反而从 2.41 升到 4.33~5.88。
因为人手上加速的快慢本来就不一样 —— 这不是裁剪能解决的，只能靠采集时控制。

## 已经排除的假设（省点时间）

这些我们都验过，**不是**原因：

| 假设 | 怎么排除的 |
|---|---|
| delta / absolute 动作搞混 | 五层（数据/配置/服务端/客户端/日志）全是绝对；反证：搞混会导致"狂奔"而不是"不动" |
| 演示数据脏 | 逐集审计，无 NaN、无跳变、帧数全对 |
| 动作头没训上 | 314 个动作头张量与基座**全部不同**（`121` 逐张量比对） |
| 欠拟合 | loss 0.08、单步误差 1.4°，早已收敛 |
| 归一化统计错 | 用 parquet 重算与 `stats.json` 逐维对账，相对差 **0.0000** |
| 两路相机不同步 | 185 个衔接点逐帧比对，0 帧差 |
| 限速截断 | 关掉 `max-rel` 结果一致 |
| 示教顺序单一 | 第一次合爪的 pan 分布 std 33.3°，本身就有多样性 |
| 相机被挪动 | `127b` 相位相关：跨 5 天位移 ≈ 0 |
| 视觉完全没用 | 把图像置黑，闭环差异巨大 ⇒ 视觉**确实**在被使用，只是精度不够 |

## 成立的根因链（v3）

1. **起点压在关节极限**
   trim 后第 0 帧 `shoulder_lift = −104.04`，物理下限 −104.3 —— 只剩 0.26° 余量。
   而模型在该位姿上输出的第一步是 `lift −7°`（真值是 `elbow −6.4 / lift −0.09`），
   于是臂被桌面顶住 → 状态不变 → 下一帧输出还是同样的值 → **永久冻结**。
   每集多裁 8 帧后，首步 lift 预测变成 **+2.47°**（k=10 时 +8.41°），`lift < −100` 的集数从 101/102 降到 22/102。

2. **视觉分辨率不足**（未完全证实，但证据链最完整）
   640×360 → 各向异性缩到 224×224 ⇒ 一个 token 覆盖原图 **38×21 px**。
   一支 25 px 宽的笔正好落在 1 个 token 里。
   现象吻合：合爪半径偏外 5~8 cm、闭环合爪方位 std 只有演示的 46%。
   判决实验（不需要重训）：**换个 ≥4 cm 宽的物体抓一次** —— 大物体稳就是尺寸问题，一样差就是别的原因。

3. **∂T/∂s ≈ 1**（`122` 实测 0.83~1.10）
   闭环纯随动、零回拉，偏差原样带走甚至放大。

4. **没有失败恢复样本**
   439 次合爪里 0 次"抓空重试" ⇒ 一旦抓空就进入分布外，永远回不来。

## 修法的优先级

按性价比排：

| 优先级 | 做什么 | 验收判据 |
|---|---|---|
| **1** | 数据每集再裁 8~10 帧（或直接改客户端起始位姿抬高 10°） | `lift < −100` 的集数 < 25/102；首步预测 lift > 0 |
| **2** | 视觉侧：裁到工作区 + 做成正方形输入，让目标跨 ~4 个 token | 合爪半径偏差 < 2 cm |
| **3** | 客户端兜底：合爪后夹爪读数 < 3 → 抬起后撤重试；拒发压向实测极限的命令 | 抓空后能返回 |
| **4** | 采集：逐集随机化起始位姿 + 失败恢复演示（DAgger） | — |

第 1 条**不需要重训**就能验证一部分（客户端改起始位姿）；
第 2 条需要重训；第 3、4 条与模型无关，但决定"能不能用"。

## 方法论：怎么避免重复这些错

1. **验收标准要在动手前写下来**，而且要写"在真机上观察到什么算成功"，
   不能是"loss 降到多少"。
2. **任何一个 teacher-forced 指标，都要问一句"如果模型学错了，这个指标会变差吗"**。
   如果答案是"不会"，它就不能用来验收。
3. **改数据的每一行，都要问"这些列的含义还成立吗"**。
   裁行不重写 `timestamp` 这个错误，本质上就是把"索引"和"内容"解绑了。
4. **对照实验只改一个变量**。例如"同一段代码加 `--no-rtc` 开关"，
   而不是"换了个脚本再比"。
5. **小心"看起来更平滑"的假象**。接缝差 0.00° 的硬钉版，手感反而更差，
   因为它把纠正也冻住了。平滑度和响应性是一对矛盾，要用数据（反向率 + 跟踪误差）权衡。
