# 07 · 诊断工具

真机上"看起来不对"的时候，光看视频猜不出来。这一组脚本的目的是**把感觉换成数字**。

先说结论，免得误用：

| 脚本 | 测的是 | 能不能预测闭环 |
|---|---|---|
| `124` 数据审计 | 数据本身有没有坏 | ✅ 能（数据坏了必然不行） |
| `127b` 画面位移 | 相机位姿是否变化 | ✅ 能（排查变量） |
| `121` 权重健康 | 权重是否损坏 / 是否真训过 | ✅ 能（排查"假模型"） |
| `96` ckpt 审计 | 每个 ckpt 的步数与结构 | ⚪ 辅助 |
| `119` 视觉消融 | 模型到底用不用图像 | ⚪ 定性 |
| `120` 开卷回放 | 单步监督误差 | ❌ **不能** |
| `122` 雅可比增益 | 闭环回拉能力 | ⚠️ 部分能 |
| `126` 输出散布比 | 是否模式坍缩 | ⚠️ 部分能 |

---

## 124 · 数据集审计

```bash
python scripts/diagnose/124_dataset_audit.py --ds /root/gr00t_data/xxx
```

统计每集帧数、关节分布、合爪次数、动作与状态的差（`action - state` 应该≈下一步的位移）。
一本正经的项目里最常坏的不是模型，是数据。

**看什么**：

- 关节 min/max 有没有贴着物理极限（`shoulder_lift` 到 −104° 就是压在桌面）
- `action - state` 的分布是否以 0 为中心（若不是，说明时间轴错位或单位错）
- 每集合爪次数分布（v3 是 2~9 次，中位 5）

---

## 127b · 相机画面位移

```bash
python scripts/diagnose/127b_view_matrix.py --ds <数据集> --episodes 0,60,101
```

用相位相关估计不同 episode 之间画面的整体位移与缩放。

**为什么需要**：跨天复用同一套标定，"相机被碰过"是最容易忽略的变量。
实测跨 5 天两次真机摆放位移 ≈ 0，仅 x 方向稳定偏 ~9 px（≈0.8 cm）——
量级远小于"抓空 5~8 cm"，可以排除相机被挪。

## 121 · 权重健康检查

```bash
python scripts/diagnose/121_weight_health_check.py --ckpt <模型目录> --base nvidia/GR00T-N1.5-3B
```

三层核验：

1. **非全零**：safetensors 头 + 多个偏移抽样，排除"大小正确、内容全 0"的假文件
2. **逐张量比基座**：backbone 585/585 应与基座**逐字节相同**（冻结），
   action_head 314/314 应**全部不同**（真训过）
3. **与训练日志对账**：`global_step` 是否等于预期步数

> 这条检查救过一次：v1 的权重曾经因为下载器只用 `truncate` 预分配 + 只比字节数，
> 变成 7.5 GB 的全零文件，而脚本还报"全部校验通过"。

## 96 · ckpt 审计

```bash
python scripts/diagnose/96_audit_gr00t_ckpt.py --dir <OUT 目录>
```

列出每个 checkpoint 的步数、文件大小、是否有 `experiment_cfg`。
用来确认"我拿到的是 20k 还是 30k"。

顺带一个省空间的发现：**最终模型与最后一个 checkpoint 的 safetensors 可能完全相同**
（md5 一致），备份时只需存一份。

## 119 · 视觉消融

```bash
python scripts/diagnose/119_vision_effect_on_target.py --model <模型> --episode 3
```

把前视图像里"目标物体所在区域"涂黑，看动作输出的变化量。

- 变化大 → 模型确实在用这块图像
- 变化小 → 它对目标位置不敏感（正是"合爪偏外"的成因）

这是定性实验，不能代替闭环验证，但能在 5 分钟内回答"视觉到底有没有起作用"。

---

## 120 · 开卷回放（teacher-forced）

```bash
python scripts/diagnose/120_replay_audit.py --model <模型> --ds <数据集>
```

把数据集里每一条演示逐帧喂给模型，比较预测动作与真值动作的误差。
v3 的结果是**中位 1.4°**，看起来完美。

### ⚠️ 但它对闭环失效结构性失明

因为每一步都喂**真值状态**，误差被锚死在 1.4°，不会累积。
模型完全可以"看着 t+63 帧的图像 + t 帧的状态"把误差拟合到 1.4° ——
这正是那个 timestamp bug 在训练集内部自洽的表现。

**记住**：loss / 回放 / 单步误差是同一个东西。它们回答"拟合得好不好"，
不回答"能不能用"。

## 122 · 雅可比增益 ∂T/∂s

```bash
python scripts/diagnose/122_correction_gain.py --model <模型> --ds <数据集>
```

对每个关节做有限差分：把输入状态 `s_j` 扰动 +2°，看输出动作 `a_j` 变化多少。

| 结果 | 含义 |
|---|---|
| ≈ 0 | 完全不看状态，纯开环 |
| **≈ 1（实测 0.83~1.10）** | **输出 ≈ 当前状态 + 常数偏移 ⇒ 纯随动、零回拉** |
| > 1 | 会放大偏差（更糟） |
| < 1 明显 | 有回拉能力，偏差会被纠正 |

这个指标第一次说清了 v3 的病因：**它不是"动作幅度小"，而是"输出跟着状态走"**。
闭环里一旦偏了 5 cm，它就带着这 5 cm 一路走下去，视觉只帮它"认相位"，不帮它"拉回来"。

## 126 · 输出散布比（模式坍缩）

```bash
python scripts/diagnose/126_grasp_sequence_probe.py --model <模型> --ds <数据集>
```

在同一段开卷回放里，统计模型在"合爪时刻"输出的方位角方差，与演示里的方差比。

| 结果 | 含义 |
|---|---|
| 比值 ≈ 1 | 输出的多样性正常 |
| **比值 ≪ 1（闭环实测 46%）** | **模式坍缩：模型给的是"平均位置"** |

v3 开卷散布比 1.09（正常），闭环只有 46% —— 又一次说明：
**同一份权重，开卷和闭环会给出相反的结论。**

## 正确的验收顺序

```
①  124 数据审计        → 数据本身没问题
②  127b 画面位移       → 相机没被挪
③  121 权重健康        → 权重是真的、没坏
④  120 开卷回放        → 拟合没问题（低 loss 不代表什么）
⑤  122 增益 / 126 散布 → 有没有回拉能力、有没有坍缩
⑥  真机日志            → ★ 唯一终审
```

第 ⑥ 步必须看的三样东西：逐关节 `act` vs `fb`、末端 FK 轨迹、合爪时的夹爪读数与位置偏差。

> 一个必须接受的事实：前五步全绿，真机也可能完全不动。
> 这个项目里 v3 就是前五步全绿、真机抓空。
